  Atari 130XE / 64K addressable, GRAPHICS 17 (full-screen GR.1, no text window)
  Addresses below PMGBASE/FONTADR/FADETAB/FDA are EXAMPLES for a machine that
  boots with PEEK(106)=160 ($A0), the typical 130XE default. Every value in
  this map is computed at init time from whatever PEEK(106) actually is.

===============================================================================
  ZERO PAGE  ($0000-$00FF)  --  who owns what
===============================================================================

   $00-$7F   OS variables (CIO, floating point, SAVMSC, ATRACT, ...).
             A few individual cells are POKEd directly by matrix.bas --
             see the OS/hardware table below. (UTIL.BIN's and FADE.BIN's
             scratch pointers live at $CB-$D1, further down this page --
             see that entry for why they're safe there.)

   $CB/$CC   FADETAB pointer in FADE.BIN; source/dest pointer in COPY,
             FLIP, MEMSET (util.asm). Shared on purpose -- see note below.
   $CD/$CE   SCRN pointer in FADE.BIN; dest pointer (COPY) / bit-reverse
             scratch byte (FLIP) in util.asm. Also shared.
   $CF       FSTEPZ -- FADE.BIN's fade-step argument, read once per call.
   $D0/$D1   CNT -- FADE.BIN's 16-bit countdown (480, the fixed screen
             size), so one loop can walk the whole table instead of the
             256-byte-max an 8-bit X register would force.
   $D4-$D9   FR0 -- BASIC's USR() return register. Every ML routine in
             this project writes its return value here and nowhere else
             in zero page.

   UTIL.BIN AND FADE.BIN SHARE $CB-$CE WITHOUT CONFLICT, 
   THEY NEVER CALL EACH OTHER

   $80-$FF   BASIC Workspace
               $80-$CA   BASIC's OWN runtime workspace 
               $CB-$D1   Specifically left unused BY BASIC ITSELF (spare
                         space inside the cartridge's own memory map) --
                         safe scratch, which is why COPY/FLIP/MEMSET and
                         now FADE.BIN all use it.
               $D2-$FF   The floating-point package's work area (FR0 at
                         $D4-$D9 included) -- only "live" DURING an active
                         FP calculation, not between statements, so it's
                         safe for a synchronous USR() call to borrow too.
